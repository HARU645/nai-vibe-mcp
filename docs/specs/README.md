# 기능 스펙

nai-vibe-mcp의 기능 설계 문서 모음. 설계 담당(사용자 + claude.ai 프로젝트 쪽 Claude)이 쓰고, 구현 담당(Claude Code)이 이 문서대로 만듦.
어떤 기능을 어느 버전에 넣을지는 [로드맵](../roadmap.md)에서 정하고, 차례가 된 기능만 스펙으로 씀.

## 진행 방식
1. 설계: 문제·목표·동작·완료 기준을 스펙으로 씀 → 상태 `준비됨`
2. 구현: 브랜치에서 스펙대로 구현하고 테스트 → PR. 스펙의 상태를 `구현 중` → `구현됨 — vX.Y.Z, PR #N`으로 갱신
3. 리뷰: 설계 쪽이 PR을 스펙과 대조해서 확인하고, 필요하면 실제 생성으로 검증 → 사용자가 머지
4. 스펙과 다르게 구현한 부분은 스펙 끝 "구현 메모"에 이유와 함께 남김 (스펙을 조용히 바꾸지 않음)

## 스펙 양식
```
# NNNN 제목
- 상태: 초안 | 준비됨 | 구현 중 | 구현됨 — vX.Y.Z, PR #N | 보류
- 목표 버전:
- 작성:

## 문제        — 지금 무엇이 왜 불편하거나 틀린지 (재현 방법 포함)
## 목표        — 끝났을 때 사용자 입장에서 달라지는 것
## 범위 밖      — 이번에 일부러 안 하는 것과 이유
## 동작        — 구체적인 처리 방식, 도구 입력·출력, 메시지 문구
## 완료 기준    — 테스트로 확인할 항목 (번호 목록)
## 릴리스      — 버전, CHANGELOG 문구, 같이 처리할 작은 것
## 구현 메모    — 구현 담당이 채움
```
