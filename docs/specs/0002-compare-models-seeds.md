# 0002 비교 시트에서 모델·시드 여러 개 한 번에
- 상태: 준비됨
- 목표 버전: v0.3.0
- 작성: 2026-10-12
- 로드맵: A2(모델 비교), A6(시드 여러 개), A3·A4(가중치 사다리·섞기 격자)

## 문제
- 2026-10-12에 작가 76명을 V4.5와 V5로 비교할 때 모델마다 시트를 따로 뽑고, 두 시트의 칸을 손으로 짝지어 나란히 붙인 이미지를 따로 만들어야 했음 (시트 14장 + 수작업)
- 시드 하나로만 보면 그 시드의 운(구도·표정)이 화풍처럼 보일 때가 있음. 시드를 바꿔 다시 보려면 시트를 다시 뽑고 또 손으로 맞춰야 함
- 가중치 단계(0.4 / 0.7 / 1.0 / 1.3)나 두 작가 비율 격자도 Claude가 칸을 하나하나 손으로 써야 함

## 목표
- `nai_compare` 한 번으로 "같은 칸을 여러 모델 × 여러 시드"로 뽑고, 시트에서 칸마다 나란히 보임
- 비용 확인은 지금처럼 시트 전체를 한 번에, 모델별 비용이 나뉘어 보임
- 가중치 사다리·섞기 격자는 Claude가 바로 쓸 수 있는 칸 작성법을 `SERVER_INSTRUCTIONS`에 넣어서 해결 (새 입력은 안 만듦)

## 범위 밖
- 가중치 사다리·섞기 격자 전용 입력(`ladder`, `mix` 같은 것): Claude가 칸 태그를 직접 쓰는 것으로 충분하고, 입력이 늘면 도구가 복잡해짐 → 안내만 추가
- 시트에 작가 이름·메모 붙이기와 `sheet.html`: 스펙 0003
- 세션 상한 안내: 스펙 0004

## 동작

### 입력 (`nai_compare`에 추가)
- `models?: string[]` — 비교할 모델 1~3개 (예: `["v4.5-full", "v5-full"]`)
  - 별명은 실제 모델 키로 바꾼 뒤(`resolveModel`) 중복을 없앰 (`"v5"`와 `"v5-full"`은 같은 모델). 순서는 처음 나온 순서 유지
  - 정리한 뒤 1개면 `model`에 그 모델을 준 것과 똑같이 동작 (같은 요청 해시)
  - `models`가 있으면 `model`과 프리셋에 저장된 모델 설정은 쓰지 않고, 결과에 한 줄 알림 ("models를 지정해서 model·프리셋의 모델 설정은 쓰지 않았습니다")
  - 모르는 모델 이름이면 지금 `model` 오류와 같은 문구로 거절
- `seeds?: number` — 칸마다 시드 몇 개로 뽑을지 1~3 (기본 1. `seeds: 1`을 명시한 것과 생략한 것은 같은 요청)
  - 기준 시드 = `seed`, 없으면 무작위 하나. 시드 목록 = 기준 시드 + 0, 1, 2를 4294967296으로 나눈 나머지 (4294967295 다음은 0)
  - 모든 모델이 같은 시드 목록을 씀

### 칸과 그림 수
- "칸" = 지금처럼 태그 하나(기준 칸 포함). 칸 수 제한은 그대로 2~12
- 그림 수 = 칸 수 × 모델 수 × 시드 수. **시트 하나에 그림 24장까지**. 넘으면 실행하지 않고 "칸을 N개 이하로 줄이거나 모델·시드 수를 줄여 주세요"처럼 줄일 방법을 숫자로 안내 (N에는 기준 칸도 포함. N이 2보다 작으면 칸 대신 모델·시드 수를 줄이라고)
- 기준 칸(`baseline`)도 다른 칸과 똑같이 모든 모델·시드로 뽑음
- 24장은 작은 크기 기준 예상 1~2분. 큰 크기에선 더 걸리므로 아래 "생성 순서와 부분 실패"의 진행 알림이 필요함. 실제 소요 시간은 설계 쪽이 v0.3 검증 때 실측해서 이 스펙에 남김
- 시트 번호는 칸 번호. `from_sheet {number}`는 지금처럼 칸 번호로 저장 (모델·시드와 상관없이 그 칸의 태그)

### 설정 정하는 순서 (`resolveCommon`이 모델 하나만 받는 구조라서)
1. 프리셋은 한 번만 읽음 (알림도 한 번만)
2. 크기를 먼저 정함: 여러 모델이면 모두 같은 크기 (공정한 비교). `size`가 없으면 모든 모델이 무료 조건(Opus + 무료 대상 모델)일 때만 `portrait`, 하나라도 유료면 모두 `small_portrait`
3. 정한 크기·스텝 등은 그대로 두고 모델만 바꿔서 모델별 설정을 만듦
4. 캐릭터 수 검사(V4.5 6명, V5 22명 등)는 고른 모델 중 가장 작은 상한으로

### 생성 순서와 부분 실패
- 칸 순서대로, 칸 안에서는 **시드 → 모델** 순서: 1번 칸 시드1 V4.5, 1번 칸 시드1 V5, 1번 칸 시드2 V4.5, 1번 칸 시드2 V5, 2번 칸 …
  - 같은 시드의 모델 쌍이 먼저 갖춰지게 (중간에 끊겨도 비교할 수 있는 쌍이 남음)
- 실패 처리는 지금과 같음: 실패한 곳에서 멈추고, 된 그림까지 시트를 만들고, 과금 가능성을 알림
  - 중단 위치는 그림 단위로: "3번 칸 V5 시드1에서 중단되었습니다: …" (지금의 "`made+1`번째 칸" 계산은 그림이 여러 장이면 틀림)
  - 시트에서 빠진 그림 자리는 회색 빈칸 + "생성 안 됨"으로 채워서 칸끼리 줄이 어긋나지 않게
- 생성은 지금처럼 하나씩 (`SerialQueue`, 동시 요청 금지)
- 그림이 많아 오래 걸리므로 두 가지를 함 (`runJobs` 공통이라 `nai_generate` 여러 장에도 같이 적용)
  - **진행 알림**: 요청에 `progressToken`이 있으면 그림 하나 끝날 때마다 "n / 전체" 진행 알림. 앱이 진행 알림으로 타임아웃을 늘려 주는지는 앱마다 다름 (SDK 기본값은 안 늘림) — 그래서 이것만으로는 끊김을 못 막음
  - **취소 따르기**: 앱이 도구 호출을 취소하면(요청의 `signal`이 abort) 지금 나가 있는 그림은 끝까지 받되, **다음 그림을 보내지 않고 멈춤**. 그다음은 부분 실패와 똑같이 정산하고, 된 그림까지 시트·기록을 남김. 중단 사유는 "사용자가 취소함"으로 (2026-10-08에 대화에서 취소한 호출이 PC에선 끝까지 실행돼 과금된 일이 있었음)

### 프롬프트 조립
- 프롬프트 조립(`composeFor`)을 모델별로 따로 함. 지금은 v4.5-full과 v5-full의 품질 태그·heavy 네거티브·nsfw 가드가 같지만, curated 모델·`quality: light`·`uc_preset: light`·V5 글자 블록(따옴표)에서는 달라짐
- 칸 태그는 지금처럼 장면 태그 앞에

### 비용 계산과 확인
- `CostEstimate`를 모델 여러 개를 담을 수 있게 넓힘: 모델별 내역 `parts: [{ model, perImage, count, free, reason }]` + 합계 `total`, 전체 `free`(모든 부분이 무료일 때만 true). 모델 하나면 지금 필드(`perImage`, `count`)도 그대로 채움
- 모델별 장 수 = 칸 수 × 시드 수
- **V5 할당량은 V5 계열 모델이 같이 씀**: v5-full과 v5-curated를 같이 고르면 두 모델의 장 수를 합쳐서 남은 할당량과 비교 (각각 따로 비교하면 무료로 잘못 예상함)
- 확인 메시지는 모델별 줄 + 합계. 예:
  - `V4.5 Full 장당 7 × 12장 = 84`
  - `V5 Full 장당 11 × 12장 = 132`
  - `합계 약 216 Anlas`
- 확인 결과(`needs_confirmation`)의 `structuredContent`에 `parts` 추가 (모델 하나면 지금처럼 `per_image`, `count`도)
- `confirm_id`가 묶이는 요청 해시: 정리된 모델 키 목록, 시드 수, 그리고 모델마다 모든 칸의 최종 프롬프트·네거티브·qt·uc (지금 compare 해시에 들어가는 항목을 모델별로). 모델이나 시드 수만 바꿔서 같은 번호로 실행되면 안 됨
- 무료 예상이 틀린 경우(`freeMismatch`)
  - 켜는 조건: 생성 전후 잔액을 **둘 다 읽었고**, 무료로 예상한 부분이 있는 시트에서 (실제 차감 − 유료 부분 예상) ≥ 무료 부분의 장당 비용 중 가장 작은 값일 때만 (유료 공식이 조금 어긋난 것만으로 켜지지 않게). 잔액을 못 읽었으면 켜지 않음
  - 켠 뒤: 모든 견적에서 무료로 예상한 부분을 유료(장당 비용 × 장 수)로 바꿔 합계에 넣음. 그래서 V4.5 무료 + V5 유료처럼 합계가 0이 아닌 시트에서도 무료였던 부분까지 확인을 받음 (지금은 `total === 0`일 때만 다시 계산함)

### 기록과 정산 (`runJobs`·`settle`이 모델 하나를 전제로 짜여 있어서)
- 작업(Job) 하나가 자기 모델·장당 예상 비용·칸 번호·시드를 들고 다님. 생성 요청 본문도 작업의 모델로 만듦
  - 작업의 장당 예상 비용 = 그 작업이 속한 모델 부분이 무료면 0, 유료면 그 모델의 장당 비용 (지금 코드의 `estimate.free ? 0 : perImage`를 작업 단위로)
- 생성 기록(`history`)은 그림마다 그 작업의 모델·장당 예상 비용으로
- 정산의 예상 차감 = 실제로 생성된 작업들의 장당 예상 비용 합. 잔액을 못 읽었을 때 과금됐을 수 있는 실패가 있으면 **그 실패한 작업의** 장당 예상 비용을 더함 (지금은 1장 값을 더함). 세션 사용량도 이 값으로
- 비용 기록(ledger)은 지금처럼 시트당 한 줄. 필수 필드 `model`은 첫 번째 모델로 채우고, 더해서 `models: string[]`와 모델별 예상 `parts`를 남김. 실제 차감은 합계만 (모델별로는 나눌 수 없음)
- 시트 조립·칸 대응은 작업 번호가 아니라 작업의 칸 번호로 (그림이 여러 장이면 둘이 다름)

### 저장
- 폴더: 지금처럼 `<날짜>/compare_<시각>/`
- 파일 이름: 모델 하나·시드 하나인 시트는 **지금 이름 그대로** `<칸 번호 2자리>_<시드>.png` (옛 동작·테스트 유지). 모델이나 시드가 여러 개면 `<칸 번호 2자리>_<모델 키>_<시드>.png` (예: `03_v5-full_20261012.png`)
- `sheet.txt`: 칸마다 한 줄 + 그 아래에 모델·시드별 실제 파일 이름
- 시트 기록(`sheets.jsonl`)
  - 칸에 `images: [{ model, seed, file? }]` 추가 (생성 안 된 그림은 `file` 없음). 기존 `file`은 그 칸에서 처음 생성된 그림으로 계속 채움 (옛 코드·`from_sheet` 호환)
  - 시트에 `models: string[]`, `seedList: number[]` 추가. 기존 필수 필드 `model`은 첫 번째 모델, `seed`는 기준 시드로 채움
  - 옛 기록 읽기: `images`가 없으면 `[{ model: 기록의 model, seed: 기록의 seed, file }]`로, `models`가 없으면 `[model]`, `seedList`가 없으면 `[seed]`로 봄
  - "생성 안 됨" 판단: 그 칸의 그림이 한 장도 없을 때
- `from_sheet`로 여러 모델을 비교한 시트의 칸을 저장할 때: 프리셋에 모델은 넣지 않고, 자동 메모를 "비교 시트 <id>의 <n>번 (V4.5 Full·V5 Full 비교, 시드 <기준 시드>)"처럼. 필요하면 사용자가 `model`을 따로 지정

### 시트 이미지 (번호만 있는 지금 방식 기준)
- 칸 하나 = 그 칸의 그림들을 가로로 붙인 묶음 (시드 → 모델 순서). 번호 배지는 묶음 왼쪽 위에 하나
- 묶음 안 그림마다 **오른쪽 위**에 작은 표시 (왼쪽 위 번호 배지와 안 겹치게): 모델 짧은 이름(`4.5`, `4.5C`, `5`, `5C`) + 시드가 여러 개면 `s1`/`s2`/`s3`
  - 이 표시에 `.`, `C`, `s` 글자가 필요하므로 **ASCII 비트맵 글꼴(지금의 5×7 숫자 글꼴 확장)은 이 스펙에서 만들고** 0003 라벨이 그대로 씀
- **시트 크기 상한: 긴 변 1600px 권장, 최대 2000px**. 그림 폭은 이 안에 들어가게 줄이되 최소 128px. 대화에 들어가는 이미지가 너무 크면 앱이 줄여서 보여 줘서 표시 글자가 안 읽히고, 시트를 여러 장 뽑는 대화에선 요청이 거절될 수도 있음
- 한 줄에 놓는 묶음 수는 이 상한 안에서 구현 담당이 정함
- 이름·메모 라벨은 0003에서 추가

### 도구 결과
- 칸마다 한 줄 + 모델·시드별 생성 여부
- `structuredContent`: `variants[].images: [{ model, seed, path }]`, `models`, `seed`(기준 시드), `seed_list` 추가 (입력의 `seeds`는 개수라서 결과에선 헷갈리지 않게 `seed_list`로)
- 쓴 Anlas: 실제 차감은 합계만 (모델별로 나눌 수 없음). 잔액을 못 읽었을 때 "약 N 사용"은 생성된 그림들의 장당 예상 합 (지금의 `perImage × made`는 모델이 여러 개면 틀림)

### 안내 문구 (해라체)
- 도구 설명에는 한 줄만: "`models`(모델 최대 3개)와 `seeds`(시드 1~3개)로 같은 칸을 모델·시드별로 나란히 볼 수 있다. 그림 수 = 칸 × 모델 × 시드, 최대 24장"
- 나머지 요령은 `SERVER_INSTRUCTIONS`의 화풍 찾기 부분에 (도구 설명은 짧게 유지)
  - 모델 비교: "V4.5와 V5에서 어떻게 다른지" 같은 요청에는 `models`를 쓴다. 비용이 모델별로 다르다는 걸 확인 때 말한다
  - 시드 여러 개: 처음 보는 작가를 판단할 때나 사용자가 "운인지 모르겠다"고 할 때 `seeds: 2`를 권한다 (비용 2배)
  - 가중치 사다리: 한 작가를 단계별로 보려면 칸을 `0.4::artist:x::`, `0.7::artist:x::`, `1::artist:x::`, `1.3::artist:x::`처럼 만든다. 라벨은 `x 0.4`처럼
  - 섞기 격자: 주 작가 1.0이면 0.5 이하 보조는 거의 안 먹는 경우가 많아서 보조는 0.7부터 (2026-10-08 실측). 예: `1::artist:a::, 0.7::artist:b::` / `1::artist:a::, 0.9::artist:b::` / `1::artist:a::, 1::artist:b::` / `0.9::artist:a::, 1::artist:b::` / `0.7::artist:a::, 1::artist:b::`
  - V5는 작가가 자주 그리는 캐릭터 특징(동물 귀·뿔)까지 따라올 수 있다. 원하지 않으면 네거티브에 `animal ears, horns` (2026-10-12 실측)

## 완료 기준
1. `models` 2개 × 칸 2개 × `seeds: 2` → 그림 8장, 순서가 칸 → 시드 → 모델 (1번 칸 s1 V4.5, s1 V5, s2 V4.5, s2 V5, 2번 칸 …)
2. 시드 목록이 기준 시드 + 0, 1. 기준 시드가 4294967295면 두 번째는 0. `seed`를 안 주면 무작위 기준 시드 하나에서 같은 규칙
3. 그림 수 25장 이상이면 생성 없이 거절되고, 줄일 방법이 숫자로 나옴
4. 확인 메시지에 모델별 비용 줄과 합계, `structuredContent.parts`. 모델 하나만 바꿔 같은 `confirm_id`로 부르면 실행되지 않고 새로 확인받음. `seeds: 1` 명시와 생략, `models: ["v4.5-full"]`과 `model: "v4.5-full"`은 같은 요청 해시
5. `size`가 없을 때: 가짜 Opus 계정 + V4.5 하나면 `portrait`, V4.5 + V5면 둘 다 `small_portrait`
6. V5 할당량: 가짜 Opus 계정의 남은 할당량이 20장일 때 v5-full 12장 + v5-curated 12장은 무료로 예상하지 않음 (`estimateCost` 단위 테스트 — 가짜 서버는 생성해도 할당량이 줄지 않으므로)
7. 중간 실패(가짜 서버 `failures`로 500) 시 앞쪽 칸은 모든 모델 그림이 있고, 중단 위치가 "N번 칸 <모델> 시드k"로 나오고, 시트의 빠진 자리는 빈칸, 시트·기록은 된 데까지
8. 정산: 모델이 섞인 시트에서 예상 차감이 생성된 그림들의 장당 예상 합과 같고, "예상과 실제 차감이 다릅니다" 알림이 잘못 뜨지 않음 (가짜 서버의 `charge`가 `body.model`별로 다르게 차감)
9. 시트 기록에 `images`, `models`, `seedList`가 남고, 옛 형식 기록도 `from_sheet`로 그대로 저장됨
10. 모델별 프롬프트 조립: `v4.5-curated` + `v5-full`(또는 `quality: light`)에서 두 모델의 최종 프롬프트가 각 모델 규칙대로 다르게 조립됨
11. 시트 이미지 긴 변이 2000px을 넘지 않음 (24장, 모델 3개 × 시드 3개 묶음 포함, 보통 크기 비율 그림 기준)
12. `models`·`seeds` 없이 부르면 지금과 결과가 같음. 기존 테스트는 전부 통과해야 하고, 이 스펙 때문에 바뀌는 테스트가 있으면 PR에 어떤 테스트를 왜 고쳤는지 적기
13. 진행 알림: SDK 클라이언트의 `onprogress`로 그림마다 "n / 전체"를 받음
14. 취소: 3번째 그림 생성 중에 AbortSignal로 취소하면 3번째까지만 생성되고 4번째 요청은 가짜 서버에 오지 않음. 정산·부분 시트·기록이 남고 중단 사유가 "사용자가 취소함"
15. `freeMismatch`: 잔액을 못 읽은 시트에선 켜지지 않음. 켜진 뒤 V4.5 무료 + V5 유료 시트의 견적에 V4.5 부분이 유료로 들어감
