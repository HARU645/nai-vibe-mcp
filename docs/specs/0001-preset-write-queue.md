# 0001 프리셋 동시 저장 시 사라지는 문제
- 상태: 준비됨
- 목표 버전: v0.2.2
- 작성: 2026-10-12

## 문제
- `PresetStore.save()`와 `delete()`(`src/store/presets.ts`)가 `presets.json`을 읽고 → 고치고 → 파일 전체를 다시 쓰는데, 그 사이에 잠금이 없음
- Claude는 도구를 한 번에 여러 개 부르는 일이 많음 (예: 비교 시트에서 고른 조합 6개를 프리셋으로 한꺼번에 저장). 그러면 두 호출이 같은 옛 파일을 읽고 각자 쓰기 때문에 먼저 쓴 쪽이 사라짐
- 도구는 둘 다 "저장했습니다"라고 답해서 사용자는 모르고 지나감 → 나중에 프리셋이 없다는 걸 발견
- 재현: 서로 다른 이름으로 `nai_preset save`를 동시에 여러 번 호출한 뒤 `list` → 일부만 남음
- 2026-10-08 실사용 중에 발견. 그 뒤로는 프리셋을 하나씩 순서대로 저장해서 피하고 있음

## 목표
- 같은 MCP 서버 안에서 프리셋 저장·삭제가 동시에 와도 전부 반영됨
- 도구 입력·출력과 메시지는 그대로

## 범위 밖
- 프로세스 사이 잠금: 같은 저장 폴더를 nai-vibe-mcp 두 개(예: Claude 데스크톱과 다른 앱)가 동시에 쓰는 경우. 드물고, Windows·OneDrive에서 파일 잠금은 오히려 문제를 만들기 쉬워서 이번엔 안 함 → README에 안내 한 줄만 (아래 "릴리스")
- `history.jsonl`, `sheets.jsonl`: 한 줄씩 덧붙이는 방식이라 이번 문제와 무관

## 동작
- `PresetStore`에 쓰기 전용 줄(`src/serial.ts`의 `SerialQueue` 재사용)을 두고, `save`와 `delete`의 "읽기 → 수정 → 쓰기" 전체를 한 작업으로 감쌈
- 줄 안에서 반드시 파일을 새로 읽고 나서 고침 (줄 밖에서 읽어 둔 데이터로 쓰지 않음)
- 한 작업이 실패해도(이름 검증 오류, 디스크 오류 등) 다음 작업은 그대로 진행. 실패한 호출만 오류를 돌려줌 (`SerialQueue`가 이미 이렇게 동작함)
- `list`, `get`은 줄에 넣지 않음. 쓰기는 임시 파일 + rename(`writeFileAtomic`)이라 반쯤 쓴 파일을 읽을 일은 없음
- 지금은 `PresetStore`가 서버당 하나(`src/server.ts`). 같은 파일을 여러 인스턴스가 쓰게 될 수 있다면 줄을 인스턴스가 아니라 파일 경로 기준(모듈 수준 Map)으로 둘 것

## 완료 기준
1. 서로 다른 이름 20개를 `Promise.all`로 동시에 `save` → `list`에 20개가 모두 있음
2. 같은 이름을 동시에 두 번 `save` → 하나만 남고, `presets.json`이 올바른 JSON이며 `created`는 처음 값 유지
3. `save`와 `delete`를 섞어 동시에 호출 → 최종 상태가 호출 순서대로 하나씩 적용한 결과와 같음
4. 앞의 `save`가 검증 오류로 실패해도 뒤의 `save`는 성공
5. e2e: MCP 클라이언트로 `nai_preset save`를 여러 개 동시에 호출 → 전부 저장됨
6. 기존 테스트 전부 통과, `npm run typecheck` 통과
