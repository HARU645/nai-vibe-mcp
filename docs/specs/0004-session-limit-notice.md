# 0004 세션 상한 미리 알림
- 상태: 준비됨
- 목표 버전: v0.3.0
- 작성: 2026-10-12
- 로드맵: F2

## 문제
- 2026-10-12에 V5 비교 시트를 이어서 뽑다가 세션 상한(1000)에 걸림. 미리 알 방법이 없어서 남은 46명을 뽑기 전에 멈추고, 사용자가 앱을 업데이트(재시작)해서 초기화해야 했음
- 상한에 걸리면 "상한을 넘게 됩니다"만 나오고, 남은 상한으로 몇 장까지 되는지는 안 알려 줌 → Claude가 칸을 몇 개로 줄여야 할지 계산할 근거가 없음

## 목표
- 큰 작업 전에 남은 상한이 보이고, 상한이 얼마 안 남으면 미리 알려 줌
- 상한에 걸렸을 때 "지금 남은 상한으로 몇 장까지 되는지"를 숫자로 알려 줌
- 상한을 올리는 건 지금처럼 **설정에서만** (대화로 올리는 방법은 만들지 않음 — 상한은 AI가 반복해서 Anlas를 쓰는 사고를 막는 마지막 장치라서)

## 범위 밖
- 하루 상한·주간 상한 같은 새 설정 (필요하면 따로 스펙)
- 사람이 직접 승인하는 MCP elicitation (로드맵 I2)

## 동작
세션 상한이 0(없음)이면 아래 안내는 모두 생략

- 남은 상한 = max(0, 상한 − 사용량) (실제 차감이 예상보다 커서 음수가 되는 경우 0)

1. **남은 상한 표시**
   - 비용 확인 메시지: 지금 있는 "이번 세션에 쓴 양: 약 X / 상한 Y" 줄을 "이번 세션: 약 X 사용 / 상한 Y (남은 약 Z)"로
   - 생성·비교 시트가 끝난 결과에도 같은 한 줄 추가 — 이번 결과에서 Anlas가 들었을 때만 (실제 차감 > 0, 잔액을 못 읽었으면 예상 > 0)
   - `structuredContent`에 `session_spent`, `session_limit`, `session_left` — `nai_generate`, `nai_compare`, `nai_account`의 결과 중 `structuredContent`가 있는 것 전부(완료, 확인 필요, 막힘, `status: "failed"`). 입력 오류처럼 예외로 끝나 공통 `errorResult`로 나가는 결과에는 넣지 않음. 상한이 0(없음)이면 `session_limit: 0`, `session_left: null`
2. **미리 알림**: 생성이 끝난 뒤 사용량이 상한의 80% 이상(= 남은 양이 20% 이하)이면 결과 끝에 알림
   - 그 세션에서 처음일 때는 긴 문구: "⚠️ 세션 상한이 약 120 남았습니다. 큰 작업 전에 설정에서 상한을 올리거나, 앱을 다시 시작하면 사용량이 초기화됩니다."
   - 그 뒤 결과부터는 짧게: "⚠️ 세션 상한 남은 약 84"
3. **상한에 걸렸을 때**: 막는 메시지에 남은 상한으로 가능한 양을 같이
   - 예: "이번 요청은 약 132 Anlas(장당 11 × 12장)인데 세션 상한이 약 36 남아서 실행하지 않았습니다. 지금 상한으로는 같은 설정에서 3장까지 됩니다."
   - 모델이 여러 개인 요청(0002)은 0002의 모델별 내역(`parts`)으로 계산. 무료로 예상한 모델은 빼고 유료 모델만 더함
   - 비교 시트면 칸 수 기준으로: 칸 하나의 비용 = 그 칸의 모든 모델·시드 그림의 유료 예상 합. "칸을 N개 이하로 줄이면 됩니다" (N에는 기준 칸 포함)
   - N이 2보다 작으면 (시트는 최소 2칸) 칸 대신 "모델이나 시드 수를 줄이거나, 설정에서 세션 상한을 올리거나 앱을 다시 시작해 주세요"
   - 가능한 양이 0이면: "설정에서 세션 상한을 올리거나 앱을 다시 시작해 주세요"만
4. **SERVER_INSTRUCTIONS (해라체)**: 여러 시트를 이어서 뽑는 큰 작업은 시작 전에 예상 합계를 세션 남은 상한과 비교하고, 넘으면 사용자에게 먼저 알린다 (상한을 올리거나 재시작하는 건 사용자 몫)

## 완료 기준
1. 비용 확인 메시지에 남은 상한이 나옴 (상한 0이면 안 나옴)
2. 사용량이 상한의 80% 이상이 되는 생성 뒤 결과에 긴 미리 알림, 그다음 결과부터 짧은 알림
3. 남은 상한 36, 장당 11, 12장 요청 → 막히고 "3장까지" 안내. 비교 시트에서 칸 하나가 V4.5(7) + V5(11) = 18이면 "칸 2개까지"처럼 칸 기준. 시드 2개면 칸 하나가 36이라 남은 36으로는 1칸뿐 → 시트는 최소 2칸이므로 칸 대신 모델·시드를 줄이라는 안내
4. `structuredContent`의 `session_left`가 완료·확인 필요·막힘·`status: "failed"` 결과에 맞게 들어감 (`errorResult`는 제외). 상한 0이면 `null`. 실제 차감이 예상보다 커도 음수가 아님
5. 상한을 올리거나 끄는 도구 입력이 생기지 않았음 (설정만)
6. 기존 비용 가드 테스트 전부 통과
